Lecture 10: Model Creation

REST API Development: Build, Test, Troubleshoot

Models are a fundamental part of REST API development. A model represents the structure of the data that the API works with. It defines the properties and types that describe a resource within the system.

By creating well-structured models, developers ensure that data can be handled consistently throughout the application, from the database layer to the API responses returned to clients.

What is a Model?

A model is a class that represents an entity in the system. For example, an e-commerce API might include models such as:

  • Product
  • Customer
  • Order
  • Supplier

Each model contains properties that describe the entity.

Example Product Model

Below is a simple example of a Product model used in a REST API:

public class Product { public int Id { get; set; } public string Name { get; set; } public decimal Price { get; set; } public int Stock { get; set; } }

This model defines the structure of product data that the API will store, retrieve, and return to clients.

Why Models Are Important

Models provide several important benefits in REST API design:

  • They define a clear data structure
  • They make the code easier to maintain
  • They allow consistent data exchange between systems
  • They help map application data to database tables

Using Models in Controllers

Controllers use models to send and receive data. For example, a controller might return a list of Product models when a client requests product information.

GET /api/products

The server processes the request and returns a JSON response based on the Product model structure.

[ { "id": 1, "name": "Keyboard", "price": 45, "stock": 20 } ]

Model Best Practices

  • Keep models simple and focused
  • Use meaningful property names
  • Use appropriate data types
  • Avoid adding business logic directly in models

Following these practices helps maintain a clean and scalable REST API architecture.

Next Steps

Now that we understand how to create models, the next step is to connect these models with controllers and implement API endpoints that allow clients to interact with the data.
