Lecture 26: Practical Guide to Automated API Testing and Variables

REST API Development: Build, Test, Troubleshoot

In this final lecture, we focus on **practical techniques for automated API testing** and how to effectively use variables in Postman to manage dynamic data across requests.

Using Variables in Postman

Variables allow you to reuse data such as API endpoints, authentication tokens, or user IDs throughout your tests. Postman supports several types of variables:

  • Global Variables: Accessible in all collections and environments.
  • Environment Variables: Specific to a given environment (e.g., dev, staging, production).
  • Collection Variables: Scoped to a particular collection.
  • Local Variables: Available only within a single request or script.

Practical Example: Using Variables

Suppose you want to create and then verify a user via POST and GET requests. Using variables ensures you can reference the created user's ID dynamically:

// Create user POST /api/users { "name": "John Doe", "email": "john@example.com" } // Store user ID in a variable pm.environment.set("userId", pm.response.json().id); // Use variable in subsequent GET request GET /api/users/{{userId}}

Automating Tests with Variables

Variables make it easier to chain requests and create robust automated tests. For example:

// Verify user email pm.test("User email is correct", function() { var jsonData = pm.response.json(); pm.expect(jsonData.email).to.eql("john@example.com"); }); // Delete user after test DELETE /api/users/{{userId}}

Best Practices

  • Use environment variables to switch between dev, test, and production endpoints.
  • Clear or reset variables after test execution to avoid conflicts.
  • Use descriptive variable names for clarity and maintainability.
  • Combine variables with pre-request scripts to generate dynamic data (timestamps, random values).
  • Integrate automated tests with CI/CD pipelines for continuous validation.

Conclusion

Mastering variables and automated testing ensures your REST API is reliable, maintainable, and ready for production. These techniques improve test coverage, reduce manual work, and enhance overall API quality.
